# Apex · Facilitator Guide for Hybrid Teaching & Learning

**Version 1.0 · June 2026**
**Companion to:** `docs/program-detail-and-agenda.md` (the 10-session arc),
`docs/program-manifest.md` (objectives & assessments), `docs/further-reading.md`.

This guide is for the people *running* Apex in a **hybrid** setting — some learners
in the room, some remote, all on the Reef-Native platform. It assumes no prior
facilitation experience and explains both the *why* and the *how*.

---

## 1. The facilitator's job in Apex

Apex is **learner-driven and simulation-centered**. The platform and the AI agents
do the heavy lifting of instruction, role-play, and first-pass feedback. Your job is
**not** to lecture content the platform already delivers. It is to:

1. **Frame** each session's big question and make the stakes feel real.
2. **Hold psychological safety** so learners will attempt, fail, and reflect honestly
   — you model the very skill Module 4 teaches.
3. **Deepen the debrief** beyond what the AI coach surfaced — connect the lived
   experience to the transferable principle (use the totem metaphors).
4. **Guarantee parity** between in-room and remote learners.
5. **Steward mastery**: track completion gates, encourage "run it back," and give
   warm, specific, evidence-based feedback.

> **Golden rule:** the learner should be talking, doing, or reflecting far more than
> you are. If you are presenting for more than ~10 minutes at a stretch, stop and
> hand it back.

---

## 2. Roles for a hybrid room

For groups above ~10, split the facilitation load across three roles (one person can
hold two for small cohorts):

| Role | Owns |
|------|------|
| **Lead facilitator** | Framing, debriefs, timekeeping, the learning arc. |
| **Remote moderator** | The chat, remote hands/voices, calling remote learners into discussion *first*, watching for dropped connections. |
| **Tech steward** | Room A/V, screen-share, platform/API health, the offline fallback, breakout logistics. |

Rotate roles across sessions so every facilitator can run any seat.

## 3. Hybrid setup that creates parity

The failure mode of hybrid is a "two-tier room" where remote learners are
second-class. Design against it:

**Room & audio**
- One shared meeting link that *everyone* joins — **including in-room learners on
  their own devices** (muted, for chat/polls/simulations). This is the single most
  important parity move: it puts everyone in the same digital room.
- A room mic that actually captures in-room voices; repeat in-room questions into the
  mic for remote learners.
- Camera framed on the facilitator and any shared whiteboard.

**Platform**
- Apex itself is Reef-Native (low-bandwidth, offline-tolerant), so simulations run
  fine on weak connections. Learners do simulations **individually on their own
  device**, in or out of the room — no shared screen needed.
- Shared artifacts (plans, pitches) live in a collaborative doc/board accessible to
  both cohorts.

**Async tools**
- A single hub (LMS page or channel) for pre-work, due dates, and reading
  (`docs/further-reading.md`). Everything dual-posted so no one misses it.

**Accessibility (build in from day one)**
- Turn on live captions in the meeting tool.
- Share slides/links *before* the session for screen-reader users and low-bandwidth
  learners.
- Offer simulation transcripts (the platform keeps the conversation on screen) so
  learners can review at their own pace.
- Universal Design for Learning: every key idea is available in **text, spoken, and
  practiced** form — which the Apex structure already provides.

## 4. The session rhythm: Arrive → Frame → Do → Debrief → Commit

Every session uses the same five-beat shape. Typical 2h15 session:

| Beat | Time | What happens | Hybrid note |
|------|-----:|--------------|-------------|
| **Arrive** | 10m | Connection check, recap last commitment, surface a quick reaction to pre-work. | Remote moderator greets remote learners by name first. |
| **Frame** | 15m | Pose the big question; make the stakes concrete; tie to the totem. | Keep it short — content lives on the platform. |
| **Do** | 45–60m | The active core: a simulation, a drill, a build, or a peer critique. | Mixed in-room/remote pairs and breakouts, not segregated. |
| **Debrief** | 30–40m | Process the experience (Kolb); name the principle; compare reads to ground truth. | Alternate calling on remote and in-room voices. |
| **Commit** | 15m | Each learner names a concrete next action and the async work due. | Capture commitments in the shared doc. |

**Why this shape:** it mirrors Kolb's cycle (Do = concrete experience; Debrief =
reflective observation + abstract conceptualization; Commit = active
experimentation). The platform's debrief agent runs this 1:1; your job is the
*collective* version that lets learners learn from each other's attempts.

## 5. Running the simulations in a session

Sessions 1, 3, and 7 center on a 1:1 AI simulation.

**Before:** confirm the live AI is healthy (see §8). Brief learners: *this is an
experiment, not a test* — set the Orientation framing every time.

**During (the facilitator's real work while learners are in their sims):**
- Learners run the sim individually (~15–20 min). You are **not** idle: circulate
  (in room) and watch the chat (remote) for anyone stuck or distressed.
- Do **not** coach mid-sim or tell learners "the right answer" — that breaks the
  experiential design. If someone is frozen, prompt process, not content: *"What's
  the smallest next thing you could try?"*
- Note 2–3 vivid moments across the cohort to reference in the group debrief.

**After:** learners get their AI debrief + score (0–8; 6 unlocks the next phase).
Then you run the **group debrief**:
- Ask volunteers to read one line they actually said and what they were going for.
- Reveal the *pattern* across the room ("most of us defended the number instead of
  asking what was behind it") — the AI debriefs one person; you debrief the cohort.
- Name the transferable principle and the totem ("this is the Devil Ray — read the
  current, don't fight it").

**"Run it back" is success, not failure.** Encourage learners below the unlock
threshold to replay with one deliberate change. The score gate exists to make
mastery the unit of progress, not to rank people.

## 6. Assessment, feedback, and mastery gating

- **Formative work is low-stakes and repeatable.** Praise attempts explicitly
  (Orientation LO; model it yourself).
- **Each module has one gating assessment** (summative for Apex/Coral/Currents/
  School/Migration; the A1 conversation for Orientation). A learner advances when the
  module's completion criteria are met — see `docs/program-manifest.md §3`.
- **The capstone** is the Migration final pitch (`the-migration-A3`), Session 10.
- **Feedback that works:** specific, evidence-based ("at *this* line you…"), and
  forward-looking ("next time, try…"). This mirrors the AI coach so learners get a
  consistent feedback voice from human and machine.
- **Grading parity:** assess remote and in-room work on identical artifacts and
  rubrics. Simulations are graded by transcript, so location is irrelevant by design.

---

## 7. Keeping both cohorts equally engaged

- **Call remote first** in roughly half of all prompts; it counteracts in-room bias.
- **Mix the pairs:** pair in-room with remote learners deliberately in breakouts.
- **Use the shared digital room** for polls and silent brainstorming so everyone
  contributes in the same channel at the same time.
- **Watch the quiet quadrant:** the remote moderator's primary metric is "has every
  remote learner spoken or typed in the last 20 minutes?"
- **Protect the debrief from the loudest voice:** use round-robin or written-first
  shares so reflection isn't dominated.

## 8. Tech & troubleshooting

**Pre-program setup (tech steward):**
- Set **`ANTHROPIC_API_KEY`** in the Vercel project (see `.env.example`). This powers
  the live AI counterpart, debrief coach, and scoring.
- Confirm a recent **production deployment is `READY`** (the platform deploys from
  `main` on Vercel).
- Create learner accounts / share the program URL; verify each learner can load a
  phase and open a simulation.

**Common issues**

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Sim shows "Offline practice mode — scripted responses" | No/invalid `ANTHROPIC_API_KEY`, or `/api` unreachable | Set the key in Vercel and redeploy; the experience still *runs* on scripts meanwhile, so a session is never blocked. |
| Score card says scoring needs the server key | Same as above | Same; learners can still debrief and replay. |
| "Simulation coming soon" on a phase | That module's scenario isn't authored yet (e.g., Coral) | Use a live group role-play for that session instead; author the scenario later (see `docs/experiential-learning-design.md`). |
| Remote learner can't hear the room | Room mic not capturing | Repeat all in-room speech into the mic; consider individual devices on the shared link. |
| Slow connection during a sim | Low bandwidth | Expected to work — Reef-Native is built for it; if it stalls, the offline fallback keeps the flow alive. |

**The graceful-degradation promise:** every AI call falls back to a scripted line if
the key is missing or the network drops, so **no session ever dead-ends**. Treat the
live AI as the default and the fallback as the safety net, not the plan.

## 9. Per-session prep checklist

For each session, the lead should confirm:

- [ ] Big question and totem framing ready (≤15 min).
- [ ] Pre-work posted and due-date set in the hub.
- [ ] If simulation session (S1/S3/S7): API health checked; "this is an experiment" framing ready; group-debrief prompts drafted.
- [ ] Breakout pairings mix in-room and remote.
- [ ] Gating assessment for the module is open and its rubric shared.
- [ ] Shared doc/board prepped for commitments and artifacts.
- [ ] Captions on; slides/links pre-shared.

## 10. Facilitator growth

Run your own Kolb loop: after each session, note *what happened*, *what you noticed*,
*the principle*, and *one change for next time*. The best Apex facilitators model the
program's own thesis — they keep shedding the shell. For depth, start with
Edmondson (2018) on psychological safety and Lang (2021) *Small Teaching*
(`docs/further-reading.md`).
